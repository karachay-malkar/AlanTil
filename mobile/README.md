# Алан тил Mobile 14.2.0

Мобильный клиент на React Native + Expo. Рабочая ветка —
`agent/14.2-mobile-parity`. Web-приложение в корне репозитория не изменяется.

## Что входит в 14.2.0

- стартовый офлайн-словарь, кэш, очередь синхронизации и раздельное хранилище аккаунтов;
- Путь, обучение выбранных слов и этапный тест по всему этапу;
- восстановление Test/Match, результаты сессий и защита от случайного выхода;
- интерфейс RU/EN/TR, профиль, настройки, избранное и песни;
- unit/contract-тесты и шесть подготовленных Maestro-сценариев.

Прохождение TypeScript, unit-тестов и Expo export не заменяет проверку APK/IPA
на устройстве. Google OAuth, сохранность прогресса при обновлении, safe area и
скриншоты размеров 320/360/390/430 проверяются отдельно.

## Запуск

Используется Node.js 24, как в GitHub Actions. Из корня репозитория:

```bash
cd mobile
npm ci
npm run typecheck
npm test
npx expo start
```

## APK для Android

GitHub Actions **Build AlanTil Android APK** запускается при отправке изменений
`mobile/` в рабочую ветку. В `main` ничего переносить не нужно.

Сборка проверяет согласованность версий, TypeScript, тесты, Android-бандл, затем
создаёт standalone release APK для **arm64-v8a** и проверяет его application ID,
версию, build number и наличие встроенного JS-бандла. Версия и имя файла берутся
из `app.json`; `package.json` и lockfile должны ей соответствовать.

После успешного запуска:

1. Открыть GitHub → Actions → **Build AlanTil Android APK** → нужный запуск.
2. В Artifacts скачать **AlanTil-14.2.0-Android-APK**.
3. Извлечь `AlanTil-14.2.0.apk` из ZIP и открыть на Android.

Артефакт **Mobile-Source** содержит исходники, а не установочное приложение.
Рядом с APK лежит SHA-256 для проверки загрузки. Артефакты хранятся 14 дней.
Это тестовая сборка; публикация в Google Play и production-подпись не настроены
этим workflow. При конфликте подписи не удалять старую версию до сохранения
локального прогресса.

## Сборки Expo EAS

Для облачной сборки нужны аккаунт Expo и привязанный EAS-проект. Профили находятся
в `eas.json`. Команды выполняются из `mobile/`.

APK для прямой установки:

```bash
npx eas-cli@latest build --profile preview --platform android
```

Подготовленные автотесты Android/iOS:

```bash
npx eas-cli@latest workflow:run .eas/workflows/e2e.yml
```

## Supabase

Значения подключения находятся в `.env.example`. Используется только publishable key. `service_role` и другие секретные ключи в мобильный клиент не добавляются.

Сценарии и матрица устройств описаны в `.maestro/README.md`. Каждый smoke-сценарий
очищает данные приложения: запускать только на тестовом устройстве/эмуляторе,
не на установленном приложении с ценным локальным прогрессом. Для физического
iPhone нужна отдельная подписанная сборка, APK для него не подходит.

## Перед приёмкой

- выполнить native E2E и сохранить эталонные скриншоты;
- проверить вход Google и возврат в приложение на Android/iOS;
- проверить офлайн-запуск, восстановление сессий и синхронизацию после возврата сети;
- проверить обновление поверх 14.1.6 без потери прогресса;
- отдельно подключить GA/Firebase, если нужна доставка расширенных событий:
  сейчас события согласия/использования сохраняются локально, общего Google-транспорта нет.
