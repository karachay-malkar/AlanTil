# Tower game — implementation contract
Base: published agent/16.8.0 at 13710ec; isolated branch agent/tower-game.
Web scope: Practice → Tower (/practice/tower); lazy isolated Three.js scene, no changes to existing learning/test navigation. Native app is not a WebGL target in this release.
Grid: 60×60, cells 25cm internally, display cells only. Height safety limit80 pending product tuning. Stretch discrete per cell, fixed price per type. Catalogue: stone1, medium4, long8, big24, beam8, deck16, window24, ladder64, roof160 silver equivalent; gold8. Door32 is provisional.
Layers: packages/tower-game/core.mjs pure geometry/catalogue/packing; src/features/tower repository/server transport; scene renderer; index UI; own CSS.
Assets: downloaded licensed CC0 source meshes/PBR, locally served, source provenance and hashes. Adapt source meshes for game geometry; no image generation. Detail textures don't substitute licensed source models.
Persistence: authoritative Supabase account balance and compact tower element arrays. get_tower_snapshot and mutate_tower; server validation, revision checks and operation receipt prevent concurrent overwrite/double debit/refund. Actual payment stored per element. No client-side mint. Guest can inspect editor but cannot spend persistent currency.
Rewards: one award per user/word with a correct result in completed test history; no repeat reward; historical backfill. Provisional difficulty mapping beginner+thematic silver; intermediate+advanced gold, versioned server mapping. Existing test APIs trust submitted results; tower doesn't increase this trust, competitive anti-cheat needs separate test protocol.
Interactions: orbit/zoom camera, catalogue sections, cell dimensions, rotation, preview, confirm, select/remove, cutaway layer, retry state. Cloud mutations require connection; no misleading saved state. Funds only change after server success.
Verification: pure boundary/overlap/support/refund/serialization tests; SQL auth/rewards/idempotency/revision tests; desktop/mobile real WebGL playtest; route/cache regression checks; full archive with file sizes; commit+push feature branch. Published branch update only after acceptance checks.
