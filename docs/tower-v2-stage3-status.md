# AlanTil 17.1 — этап 3, контролируемое внедрение

## Что реально реализовано

- Независимый JS-решатель непрерывных координат `packages/tower-game/stone-placement-v2.mjs`.
- `stone-mesh-adapter.mjs`: преобразование тех же 23 PACK-моделей, что отрисовывает Three.js, всеми 8 существующими ориентациями. Контракт по координатам: solver — метры; legacy UI — целые ячейки по 0,25 м; позиции сохраняемых элементов остаются прежними.
- `tower-v2-proposals.mjs`: отказ по некаменным старым элементам, недопустимым формам, границам участка и отсутствии опоры. Исходные камни не сдвигаются.
- `src/features/tower/stone-placement-v2-worker.js`: поиск вне главного потока с защитой по revision и ключу задачи; новейший запрос имеет приоритет.
- Опциональная интеграция с настоящей сценой: `?tower_v2_preview=1`. Луч камеры по центру экрана даёт точку в метрах; экспериментальный силуэт виден в существующей сцене. Координаты и форма настоящих камней сохранены. Без параметра поведения сайта не меняются.
- Экспериментальный режим **строго только для предварительного просмотра**: кнопка установки отключена; `submit()`, подтверждение, удаление и обмен валют заблокированы на пути к RPC; любые старые башни сохраняются в оригинальном формате.
- Отдельный браузерный QA: WebGL/Canvas, отображение зелёного силуэта, дробные координаты, работа Worker, отказ в вызове mutation, размеры мобильного экрана.

## Почему это пока НЕ полноценный этап 3

**Серверная безопасность:** `private.tower_place_valid`, `private.tower_world_element`, `private.mutate_tower` на Supabase до сих пор основаны на INTEGER / AABB. Если включить новый координатный контракт без зеркального серверного SAT/контакта, клиент сможет отправить пересекающиеся камни. Переход требует схемы v2, версионированного формата, проверки на сервере тех же сериализованных исходных объёмов, идемпотентности/revision и миграционных тестов. **Без этого запрещено отправлять grid-free placement в production.**

**Опора:** проверяется дискретной сеткой проб 15×15 по оригинальным треугольникам и консервативной оболочкой SAT; это не доказательство динамической устойчивости (контактная поверхность и центр тяжести приближённы).

**Забутовка и подгонка:** остались прежними в настоящем приложении. Не заменены алгоритмы `masonry-contact.mjs` / `masonry-packing.mjs`, потому что они рассчитаны на AABB-соседство и после миграции нуждаются в новой схеме поиска полостей. Текущий алгоритм не меняет никакие грани камней.

**Рендер:** диагностика текущих 23 моделей выявила 646 открытых граничных рёбер, но конфликтов направлений по парным рёбрам нет; чёрные поверхности не считаются исправленными. Нужна проверка физических Android/WebGL-устройств и локализация проблем освещения, теней, нормалей, видимости и GPU-драйверов.

**Производительность:** браузерный Web Worker сохраняет отзывчивость UI, но не гарантирует задержку подбора. Нужны замеры на Android при 50+ камнях и пространственный индекс. Текущий поиск ограничен до 24 вариантов и не предназначен для каждого кадра.

## Запуск

- Обычная игра: без параметра URL, прежние сохранения/экономика.
- Только разработка: добавить к странице `tower_v2_preview=1` в query string и открыть экран башни. Будет виден предупреждающий ярлык «демонстрация без сохранения» и заблокирована установка.
- `node --test tests/tower-v2-*.test.mjs` — новый решатель, геометрия 23 реальных PACK-мешей, камера, fail-closed и безопасность RPC.
- `node --test $(find tests -maxdepth 1 -type f -name 'tower-*.test.mjs' ! -name 'tower-immersive-17.test.mjs' | sort)` — рабочие регрессии.
- `tests/tower-immersive-17.test.mjs`: два исходных устаревших утверждения о `17.0.16` и прежнем расположении анимации, выполняются отдельно с пометкой «не блокирует» в CI.
- `scripts/qa/browser-tower-v2.cjs` — браузерный тест на GitHub Actions, подставляет тестовый `repository.js` без реального Supabase.

## Интеграционный контракт на следующий этап

1. Добавить `tower_elements_v2` с физическими координатами (метры), ориентацией, исходной моделью/вариантом и версией геометрии.
2. Сделать серверную валидацию геометрии (SAT/BVH) и опоры через доверенный модуль или endpoint, а не через клиентский флаг. Старый RPC — только для старых элементов.
3. Реализовать atomically placement + currency debit + revision/receipt, откат и replay idempotency.
4. Переход для башен, содержащих некаменные элементы, считать отдельно. Не смешивать legacy AABB со свободным пространством без единого collision oracle.
5. Только после прохождения GPU/Android и серверных тестов разрешить сохранить свободно размещённый камень.
