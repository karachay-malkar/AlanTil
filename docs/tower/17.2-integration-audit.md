# AlanTil 17.2 — секционная кладка: технический аудит

Базовый HEAD до работы: `0c24697bff3db59d180e012f1a04086996f21e23`. Это проверка кода и live-схемы Supabase, **не** успешный браузерный прогон.

| Компонент | Фактическая проблема | Точка интеграции |
|---|---|---|
| `src/features/tower/index.js` | Основной каталог и размеры остались от старого редактора; `v2Enabled=true` меняет алгоритм предложения позиции, но не логику секций | `mount`, `renderCatalog`, `chosen`, `updatePreview`, `submit` |
| `scene.js` | `sectionStones` нарезает регулярные объемы, а не решает физическую укладку. Ветка `key.includes(':contact:')` в `rebuild` недостижима | новая секционная геометрия и рендер по отдельным исходным камням |
| `scene.js` | `rebuildMasonry` отключает весь расчёт забутовки, если активен `enableV2Aim` | подключить отдельный рассчитанный секционный Worker |
| `masonry-contact.mjs` | `deformContactMesh` уже умеет локальную деформацию, но не задействован для V2-камней в текущем рендере | использовать в секционном Worker, проверять инверсии граней |
| `masonry-packing.mjs` | Реальная забутовка из оригинальных каменных мешей уже существует, но ориентирована на стыки старых камней. Worker передаёт корректные typed arrays | адаптировать поиск действительных полостей и бюджеты |
| `rock-shapes.mjs` и `processed-rocks.mjs` | Доступно 23 утверждённых исходных неправильных меша | повторное использование без примитивных кубов или сфер |
| `tower-v2-proposals.mjs` | Геометрический поиск для одиночного камня; прямо обозначен экспериментальным | новый поиск для секций, серверная перепроверка |
| `repository.js` | RPC V2, нет версии 3 | новый серверный снимок и идемпотентная транзакция |

**Live Supabase:** проверены таблицы `private.tower_accounts`, `private.tower_receipts`, `private.tower_v2_shapes`, `private.tower_v2_elements` (RLS включён). `mutate_tower_v2` разрешает только `medium`, `long`, `big` с серверными ценами 4, 8, 24 серебра. Эти цены **не** являются утверждёнными ценами новых пяти секций. Направлять новую секцию в старый RPC или списывать баланс на клиенте запрещено.

## Что реализовано как независимый фундамент

- Пять секций 1×1×1, 2×2×2, 2×2×3, 2×3×4, 4×4×4 в единицах по 25 см.
- Детерминированные математические оболочки отдельных неправильных камней; сохранена связь с авторскими моделями.
- Обнаружение стыков между секциями и список зависимых соседей.
- Несеточные варианты расположения и предварительная проверка опоры (не серверный критерий).
- Рендерная сборка с оригинальными треугольниками; модуль взаимодействия с прежними контактами и забутовкой в Worker.
- Контракт сохранения v3 и неразрушающее чтение старых башен.
- Автоматизированные проверки и workflow для полного ZIP исходников.

## Блокирующие условия окончательной интеграции

1. Исходные отдельные `AlanTil_17_2_wall_test.zip`, `AlanTil_17_2_section_prototype.zip`, `AlanTil_17_2_3D_viewer.html` в текущих Project/Library-источниках не найдены. Для точного сравнения их код понадобится снова.
2. Математическое заполнение оболочек ещё **не доказывает** плотность реальных 3D-мешей. Нужны метрики соприкосновения, пересечений, забутовки, нагрузки и сравнение на стене/угле.
3. Новые цены по ТЗ отдельно утверждаются. До этого новая покупка и серверная миграция в действующую БД не включаются.
4. В текущем UI всё ещё старый редактор. Необходимо внедрить новые модели и рендерер в единственный маршрут, заменить каталог и тестировать реальные платежи/сохранения/мобильные жесты.
5. Цели производительности и браузерное качество пока не подтверждены на устройствах.

**Защита прогресса:** текущие RPC, баланс, исторические блоки и Supabase-схема не изменены. Внедрённые модули не включают неавторизованные покупки.
