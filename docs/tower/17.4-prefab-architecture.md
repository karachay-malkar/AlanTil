# AlanTil 17.4 — Final prefab-section architecture

Branch baseline: `17.2` @ `5833130126215e1bc8b254a1273721776c442e9f`.

## Approved final design

One tower editor with five prefabricated masonry section sizes, in units of 25 cm:
`1x1x1`, `2x2x2`, `2x2x3`, `2x3x4`, `4x4x4`.
Every section is a fixed, offline-produced mesh from the supplied 36 authored rock models.
Four visual variants are baked per size. Three authored joint assets are prepared offline.
No individual-rock purchases, runtime random masonry generation, dynamic stone deformation,
voxel packing, or active classic/free-mode switch are part of the player editor.

### Offline asset pipeline

- Original user-supplied file, verbatim: `assets/tower/source-original-36.glb`.
- Reproducible standalone compiler: `tools/tower/build-prefab-library.py`.
- Runtime assets: `assets/tower/prefabs/manifest.json`, 20 pre-baked section GLBs and 3 joint GLBs.
- Source meshes are welded with UV/normal split vertices unified, then verified watertight before export.
- All triangles in output come from original meshes; no procedural cuboids or synthetic stone meshes.
- Source and resulting mesh count, dimensions and deterministic asset identifiers are listed in the manifest.
- The `trimesh`-based compiler is an **offline development tool** and is never imported or executed by the app.

### Runtime

- `src/features/tower/index.js`: sole tower editor and catalog. Static prefab manifest, five types, four variants, drag-free placement, click-to-adjoin and single 3D scene.
- `src/features/tower/prefab-scene.js`: native Three.js GLTFLoader, shared prebuilt mesh cache, view + placement ghost + fixed seam GLB instances; no geometry solver.
- `packages/tower-game/prefab-layout.mjs`: deterministic envelope collision and support checks for local placement previews only. This must NOT be used as the authoritative server solver.
- `src/features/tower/repository.js` and `packages/tower-game/core.mjs` remain untouched for historical paid V1/V2 loading, wallet accounting and serialization.
- Historical user-paid elements are read-only; no forced migration, remapping of paid IDs, deletion, refund or V2 mutation is performed.

### Honest release limitation

**No prices for the five new prefabs have been approved.** The new editor therefore saves draft
sections only in `localStorage`, clearly labels the state as a **local unpurchased draft**, and never invokes a paid mutation RPC. This is not a substitute for authoritative V3 server storage.

New purchases must remain disabled until prices are agreed and the V3 transaction system is implemented. Do not silently enable V1/V2 billing to charge for sections. Do not convert paid V2 stones into new section IDs without a separately verified reversible migration.

### Required V3 transaction contract before purchases

A server-owned V3 table stores section ID, prefab size ID, variant, rotation, coordinates, pinned asset version, owner ID, revision, and paid currency/amount. All inserts/deletes and balance adjustments execute in one transaction, with idempotency key, RLS, server-side price lookup and collision/support verification. Legacy reads remain available. Do not trust client `validatePrefabPlacement` for security or physics.

### Deleted experiments

Deleted old per-rock placement and StonePacking/V2 preview modules, section layout/pipeline/workers, dynamic contact/infill generators, old scene, unused dual-mode UI tests and obsolete branches' CI workflows **only in target branch 17.2**. Old SQL migrations are deliberately preserved to keep deployed database and existing paid V1/V2 data compatible.

### QA

- Node tests for all five sizes, variant assets, prefabricated-seam connectors, placement collision and real support, legacy paid-data preservation.
- CI checks all 23 GLBs against original source SHA and watertight topology.
- CI real WebGL test on desktop/mobile with preview, local save, reload, unchanged wallet and no mutation requests.
- Visual assessment must still check natural morphology, seam quality, gaps and repetitions. Automated topology and runtime tests do not prove aesthetic completion.
